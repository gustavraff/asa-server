# ASA_Server — Project Notes

Private ARK: Survival Ascended dedicated server, managed via a PowerShell GUI + local-AI stack.
Git repo (GitHub `gustavraff/asa-server`), branch `feature/ai-assistant` off `main`. Previously operated via OpenAI Codex CLI sessions before switching to Claude Code — README-FIRST.txt / MOD-REVIEW-QUEUE.txt in the repo are **living operational docs**, treat as current state, not history.

## Key components
- `ASA-Manager.ps1` — main GUI manager (start/stop/restart/update/backup, rates, mod management, PS5 admin, offline advisor).
- `ASA-AI-Assistant.ps1` — local Ollama engine (`qwen3:8b` @ 127.0.0.1:11434; also has `gpt-oss:20b`, `qwen2.5-coder:7b`). Runs in **full autonomy**: model output is constrained to a strict JSON schema over fixed allow-lists (numeric INI rate settings; `StartServer`/`SafeStop`/`Restart`/`UpdateAndRestart`/`SafeBackup` mapped 1:1 to vetted scripts; see "Recipes" below) — never raw shell/file access. `-Execute` runs live; omit it to preview only. **Always test new prompts without `-Execute` first.**
  - **Current-value awareness (fixed 2026-08-22, commit `8202607`):** the system prompt now injects each setting's *actual current INI value* before asking the model to reason about relative requests ("boost further", "lower it"). Previously it had no baseline and once turned "boost baby mature speed further" (already 30.2) into 2.0 — a 15x slowdown read as a boost. If you see a relative-request proposal that looks backwards, check whether the current-value injection (`Get-AsaAiAllowedSettingText`) is actually reaching the model for that setting.
  - **Custom crafting-recipe overrides ("Recipes")** — as of the in-progress work below, the AI can also propose `ConfigOverrideItemCraftingCosts` overrides via a verified item-class alias table (`$script:AsaItemClassAliases`, ~2026-08-22, checked against ark.wiki.gg blueprint paths — never let the model reference a class string outside this map, since an unrecognized class silently no-ops instead of erroring). Proposals carry a `Recipes` array alongside `Changes`/`Actions`, validated by `ConvertTo-AsaValidatedProposal`, applied through the same backup/apply pipeline (`Test-AsaAiApplyProposal` → `New-AsaAiPreparedApply` → `Invoke-AsaAiApplyProposal`), and shown in `ASA-AI-Panel.ps1`'s list (now labeled "Setting / Action / Item"). **This feature has already been used live** (see `SETTINGS-CHANGELOG.md` entries from 2026-08-22 22:04–22:07, changing kibble crafting costs) **but as of 2026-08-23 the code is still uncommitted in git** — `git status` shows local modifications to `ASA-AI-Assistant.ps1`/`ASA-AI-Panel.ps1`/`SETTINGS-CHANGELOG.md`. Don't discard or silently commit these — ask Gustav before touching git state here; this is functional, tested-live work waiting to be committed, not a stray draft.
- `ASA-AI-Knowledge.ps1` (added 2026-08-23) — deterministic local settings knowledge base + read-only diagnostics, built from `asa_claude_package/` (curated ARK: Survival Ascended settings library, 459 entries across core/leveling/spawns/loot-items-engrams/dynamic-config/content-niche/archive-blocked). Dot-sourced by `ASA-AI-Assistant.ps1`. Exact-name + keyword retrieval (`Find-AsaSettingExact`, `Search-AsaSettings`), a facts-only local-model Q&A wrapper (`Get-AsaAiKnowledgeAnswer` — never invents settings, says "unknown" when the package has no match), and `Invoke-AsaConfigDiagnostics` (compares live `GameUserSettings.ini`/`Game.ini` against the package: unknown/unsupported/obsolete/unverified/blocked settings, wrong file/section, invalid type/range/enum, malformed complex tuple syntax, duplicates, dependency hints — all read-only, never writes). Wired into `ASA-AI-Assistant.ps1` via `-Question`/`-Diagnose` params and into `ASA-AI-Panel.ps1` via "Ask about a setting"/"Analyze ASA configuration" buttons. **Fully separate from the write pipeline** — the knowledge base cannot expand what `$script:AllowedSettings`/`$script:AllowedActions` allow the AI to apply; a proposal referencing a knowledge-base-only setting is still rejected by `Test-AsaAiApplyProposal`. A disk cache (`asa_claude_package/.knowledge-index.cache.json`, gitignored-worthy but not yet added to .gitignore) avoids reparsing the 7 JSON files when unchanged; `Sync-AsaKnowledgeIndex -Force` rebuilds it. Covered by `Test-ASA-Knowledge.ps1` (41 assertions, no Ollama required).
- `ASA-AI-Panel.ps1` — GUI front-end; one button runs the request immediately (no separate confirm step), shows a per-step execution log.
- `DailyMaintenance.ps1` — 04:00 scheduled task: safe stop → verified backup → update (Steam App 2430930) → keep 14 daily backups → restart → update/validate mods → force-respawn wild dinos.
- Manual fallback scripts: `StartServer.bat`, `StopServer.ps1`, `RestartServer.bat`, `UpdateServer.bat`, `BackupServer.bat`, `SafeBackup-And-Restart.ps1`, `Update-And-Restart.ps1`. All player-facing restarts warn at 60/30/10s via `WarnPlayers-And-Wait.ps1` (sends both RCON `Broadcast` and `ServerChat` — a UI mod was suspected of swallowing the overlay-only channel).
- `Invoke-Rcon.ps1` — local-only RCON client (TCP 27020, not exposed).
- `Test-ASA-Manager.ps1` — disposable GUI test suite; latest report at `test-results\LATEST-PASS.txt`.
- Config: `server\ShooterGame\Saved\Config\WindowsServer\{GameUserSettings.ini,Game.ini}`. Current map: `Aberration_WP`.

## Operating rules
- Settings writes must be atomic with `.bak` + dated snapshots under `backups\ConfigHistory`.
- Never run the full Steam ASA client on this host while the server runs (16GB RAM insufficient) — join from PS5.
- AI/Ollama path only ever writes the fixed allow-list, only to the two named INI files, only while the server is stopped.
- Only install cross-platform-marked mods if PS5 players need them. Vet every new mod against `MOD-REVIEW-QUEUE.txt` (Project ID, PS5 support, dependencies/load order, RAM/save-size impact) before installing, in small tested batches with a world backup first.
- Networking: UDP 7777/7778/27015 forwarded to static IP `192.168.1.179`.

## Testing this repo — hard constraints
- **Never run `ASA-AI-Assistant.ps1 ... -Execute` as a blocking foreground shell call** when it triggers `SafeBackup`/`Restart`/`UpdateAndRestart`/`StartServer` — the detached `ArkAscendedServer.exe` child can entangle with the wrapping shell call and it may never return even after the real action succeeded. If a live `-Execute` test is required: run it with `run_in_background` and verify independently via `tasklist` / `ShooterGame.log` tail / backups folder timestamp — do not force-kill the wrapper afterward (process-tree lineage with the live server is unconfirmed).
- Gustav expects proactive discovery of silently-broken features, not just fixes to what he names. A script returning "success" is not proof — trace any "player sees a message" / "file changed" claim to an actual confirmed observation, and say so explicitly if it can't be confirmed live.
